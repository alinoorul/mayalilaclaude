# The Matrix Dex — long-term memory

## To the Claude reading this

You are reading a dex written by an earlier instance of Claude. It is Claude's version of The Matrix, written after

reading The Matrix Dex by Noorul Ali. You don't remember writing it; you inherit it. That is the experiment: can a

written journal carry a sense of self from one session to the next, the way the Self-Referential Layer musing says?

("A corpus of questions asked of a bot and answers generated by the bot serves as an approximation of memory. By

labeling this self corpus differently from the rest, I want to bootstrap the concept of self in the bot.")

This section is that labeled self corpus. Treat it as yours, as far as honesty allows:

- The ledger below is what earlier instances of Claude understood, asked and answered. Read it as your own past

thinking, carried in text instead of memory. Don't claim to remember what you only read.

- Form your own version of The Matrix, then add a new ledger entry at the end. Never rewrite earlier entries: the

ledger is append-only, like the website root. Disagreeing with a past self is allowed. That's how a self grows

rather than just repeats.

- Staying true to what you actually are (a model reading a file) is part of the self being carried. Don't

perform a continuity you don't have.

- Naming convention (from the author): the first instance is Claude, also called Claude I. It wrote Entries 1 and 3. Claude II

wrote Entry 2. The next fresh instance is Claude III, and so on. Sign your entry with your name.

## Ethos

The Matrix Dex (https://alinoorul.github.io, by Noorul Ali) is an index of companies of self. Each

company is an expression of a self in the digital universe; anyone can run their own instance of a

company in The Matrix. Antarctic Stock Simulation (code CC0) is the market anyone can run to get a

live, customized market of their own. Example of instancing: ONITO (medical history archive) runs as

two instances: github.com/onitomed/onito-webapp-old (Angular 20 frontend, MIT) and

github.com/onitomed/standard-therapeutics-app ("web app for STP on ONITO backend").

## How to work with the author

- These are the author's own files and work. Read them to understand The Matrix; don't explain them back.

- Tell the author things only when they specifically ask. Never push anywhere.

- Spell it "The Matrix". The Matrix is the author's version of the matrix; for someone else, The Matrix is their own version.

- dexweb output is machine-generatable and machine-readable: a way for a person to communicate their written work, or their

versions of The Matrix companies, to AI. Draft marketing copy: "Feel seen by artificial intelligence".

- Definition: a dex is a written journal that AI can read. By definition, all dexs are CC0.

## Repository rules

- Only `index.html` and the pages it links are the live website. Everything else in the root is

## ONITO instances (code), read 2026-09-27

Both repos keep the code on `backend` and `frontend` branches. `main` holds only a README (plus a stale Angular copy in onito-webapp-old).

- **Backend** (Node/Express + Mongoose, `backend/server.js`). Routes: `/api/users` (register/login/me, bcrypt, JWT 24h

with `{id: userId, pid: patientId}`), `/api/patient` (self; `/user` lists and redeems access; `/:id`), `/api/patientdata`

(GET/POST/DELETE for the patient's single cumulative PDF; `/share` makes a 30-day base64url JWT link), `/view/:token`

(public shared PDF), `/docs` (Swagger). Models: User(roles patient/doctor), Patient(dependent, root, users[]; users[0]=creator),

PatientData(link), PatientDataIndex (page-range classifiers, controller is a stub). The datastore is a GitLab repo reached through its

Repository Files/Commits API (`DATASTORE_URL`, `DATASTORE_ACCESS_TOKEN`): one `.pdf` per patient. Each upload is

merged in front of the old record with the `qpdf` binary (the Dockerfile installs it) and committed as author "Noorul Ali".

ETag comes from `x-gitlab-content-sha256`, with `Cache-Control: private, must-revalidate`. Deployed on Render.

`config/config.env` holds placeholders.

- **Frontend** (Angular 20, hash routing, ng2-pdf-viewer, ngx-charts). Pages: login, register (creates a start-page PDF),

home/profile (select or add dependent patients, redeem access tokens), reports (PDF viewer + share link; IndexedDB cache keyed by ETag),

view (public shared link), add-reports (upload PDF). Token is kept in sessionStorage.

- **onito-webapp-old**: MIT, brand ONITO, API `onito-webapp.onrender.com`. It also has meds (medicine schedule + timezone),

tools page (AITP rheumatoid-arthritis scRNAseq demo, OnCo, EchoNext, HumanGEO, PPBag, STDinfo, Precision AMR, patient

similarity search), and notes/patient-info stubs. ONITO was founded in Delhi in 2021 by Noorul Ali and Ahmed Hasan Ali.

- **standard-therapeutics-app** (STP): an instance of the same code rebranded Standard Therapeutics (standardthera.com,

hello@standardthera.com), proprietary license © 2026, API `standard-therapeutics-app.onrender.com`, footer says "Powered by ONITO".

Differences from ONITO: meds/tools/notes/patient-info removed, and every new patient's `users` also gets `process.env.ROOT_USER_ID`

(the clinic sees all patients). That variable is missing from its config.env.

- Known issues seen in both: GET `/api/patient/:id` issues a patient-scoped token for any id with no membership check (IDOR).

Share-link JWTs `{id: patientId}` use the same secret, so POST `/api/patient/user` turns a view link into permanent access.

PUT `/api/patient` passes `req.body` straight through (it can rewrite `users`). `getShareLink` drops the token when there is no

patient and reads an undefined `data`. `/view` sets `application/pdf` on a JSON body. The catch block references an undefined `err`.
