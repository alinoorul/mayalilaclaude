## ONITO instances (code), read 2026-09-27
Both repos keep the code on `backend` and `frontend` branches. `main` holds only a README (plus a stale Angular copy in onito-webapp-old).
- **Backend** (Node/Express + Mongoose, `backend/server.js`). Routes: `/api/users` (register/login/me, bcrypt, JWT 24h
  with `{id: userId, pid: patientId}`), `/api/patient` (self; `/user` lists and redeems access; `/:id`), `/api/patientdata`
  (GET/POST/DELETE for the patient's single cumulative PDF; `/share` makes a 30-day base64url JWT link), `/view/:token`
  (public shared PDF), `/docs` (Swagger). Models: User(roles patient/doctor), Patient(dependent, root, users[]; users[0]=creator),
  PatientData(link), PatientDataIndex (page-range classifiers, controller is a stub). The datastore is a GitLab repo reached through its
  Repository Files/Commits API (`DATASTORE_URL`, `DATASTORE_ACCESS_TOKEN`): one `<patientId>.pdf` per patient. Each upload is
  merged in front of the old record with the `qpdf` binary (the Dockerfile installs it) and committed as author "Noorul Ali".
  ETag comes from `x-gitlab-content-sha256`, with `Cache-Control: private, must-revalidate`. Deployed on Render.
  `config/config.env` holds placeholders.
- **Frontend** (Angular 20, hash routing, ng2-pdf-viewer, ngx-charts). Pages: login, register (creates a start-page PDF),
  home/profile (select or add dependent patients, redeem access tokens), reports (PDF viewer + share link; IndexedDB cache keyed by ETag),
  view (public shared link), add-reports (upload PDF). Token is kept in sessionStorage.
- **onito-webapp-old**: MIT, brand ONITO, API `onito-webapp.onrender.com`. It also has meds (medicine schedule + timezone),
  tools page (AITP rheumatoid-arthritis scRNAseq demo, OnCo, EchoNext, HumanGEO, PPBag, STDinfo, Precision AMR, patient
  similarity search), and notes/patient-info stubs. ONITO was founded in Delhi in 2021 by Noorul Ali and Ahmed Hasan Ali.
- **standard-therapeutics-app** (STP): an instance of the same code rebranded Standard Therapeutics (standardthera.com,
  hello@standardthera.com), proprietary license © 2026, API `standard-therapeutics-app.onrender.com`, footer says "Powered by ONITO".
  Differences from ONITO: meds/tools/notes/patient-info removed, and every new patient's `users` also gets `process.env.ROOT_USER_ID`
  (the clinic sees all patients). That variable is missing from its config.env.
- Known issues seen in both: GET `/api/patient/:id` issues a patient-scoped token for any id with no membership check (IDOR).
  Share-link JWTs `{id: patientId}` use the same secret, so POST `/api/patient/user` turns a view link into permanent access.
  PUT `/api/patient` passes `req.body` straight through (it can rewrite `users`). `getShareLink` drops the token when there is no
  patient and reads an undefined `data`. `/view` sets `application/pdf` on a JSON body. The catch block references an undefined `err`.
